### P1 — #13 resolves symlinks before rejecting them

At [session_workspace.py:115](https://github.com/BrandNewDevs/WorkBench/blob/3e5a42fdae0f9e1f33d281aadd16d23486064599/apps/ai/app/storage/session_workspace.py#L115), `_contained_path` resolves the destination before `_reject_symlink` inspects it. A link to another session remains inside the shared sessions root, passes containment, and causes `os.replace` to overwrite the other session's file. This requires an existing symlink; no race is needed.

Reproduced with real temporary files on macOS:

```python
store = LocalSessionWorkspaceStore(Path(directory) / "sessions")
a = store.create_session_workspace("first")
b = store.create_session_workspace("second")
victim = store.save_file("second", WorkspaceArea.ARTIFACTS, "note.txt", b"original")
(a.uploads / "report.txt").symlink_to(victim)
store.save_file("first", WorkspaceArea.UPLOADS, "report.txt", b"overwritten")
assert victim.read_bytes() == b"overwritten"
```

Reject links on the unresolved destination, enforce containment within the requested session/area, and add cross-session and cross-area link regressions. Windows junction behavior also needs target-platform coverage; it was not tested here.

### P2 — #10 image normalization ignores its output pixel limit

At [normalizer.py:195](https://github.com/BrandNewDevs/WorkBench/blob/9e0ba7b02c8791a489d0a4af5229ca8f827bc4fe/apps/ai/app/ai/vision/normalizer.py#L195), image thumbnails honor `max_long_edge` but not `max_rendered_pixels`. With the latter set to 262,144, an 1800×1800 PNG produced 3,240,000 output pixels. The PDF path uses both limits; the image path does not.

Derive the image scale from both bounds and verify the final dimensions. This matters when operators lower the pixel budget for a constrained workstation.

### P2 — #10 blocks the async service during image processing

At [analyzer.py:43](https://github.com/BrandNewDevs/WorkBench/blob/9e0ba7b02c8791a489d0a4af5229ca8f827bc4fe/apps/ai/app/ai/vision/analyzer.py#L43), the synchronous normalizer iterator performs file reads, PDF rendering, resizing, and PNG encoding on the event-loop thread. Awaiting model inference afterward does not make that work asynchronous.

A real 4000×4000 PNG normalized through `VisionAnalyzer`, with only model output replaced by a yielding stub, delayed a 1 ms heartbeat to 116 ms. This measures preprocessing, not inference. Run decoding through a bounded worker while keeping page/model processing sequential; do not decode the whole document concurrently into memory.

### P1 — #11 startup fails in supported development environments

At [dev.mjs:9](https://github.com/BrandNewDevs/WorkBench/blob/23aff433d9377db76136c1c2b9f35a308cbb5fe8/apps/desktop/scripts/dev.mjs#L9), the Windows command is `pnpm.cmd`, then passed to `spawn` with `shell: false`. Windows command wrappers need a shell; see [Node's child-process documentation](https://nodejs.org/api/child_process.html#spawning-bat-and-cmd-files-on-windows). This Windows failure is identified from code and documented platform semantics, not a Windows run.

Independently reproduced a launch crash on this macOS agent host: inherited `ELECTRON_RUN_AS_NODE=1` caused `BrowserWindow` import failure. The working branch now uses Vite's API, spawns only the Electron executable, removes that inherited flag, and forces the bundled renderer for `start`. Development startup and draft switching were verified in the native app.

### P2 — #11 successful session revalidation discards local drafts

At [App.tsx:342](https://github.com/BrandNewDevs/WorkBench/blob/23aff433d9377db76136c1c2b9f35a308cbb5fe8/apps/desktop/src/renderer/App.tsx#L342), expiry sets `revalidating`. Because `useChatThreads` is owned by `Workspace`, successful renewal mounts a fresh thread store and loses all drafts and selections.

This is a code-path finding; live authentication is not implemented, so this scenario was not exercised against FastAPI.
